# Project profile

What this repository actually chose, line by line, with the section of the working plan (`docs/plans/dashboard-plan.md`, local) or of `STYLE.md` each answers to. Started at DP-0 (2026-10-15); every phase's "as built" updates the lines it touches. A line that says "not yet" names the phase that settles it.

## Decisions and requirements

| --- | --- | --- |

| P2-D3 | Events in PostgreSQL first, behind a store interface; the query API serves the tree's documents at the tree's paths, so the app reads them with the source it has (`dataRoot` `/api/data`) | ADR-0007; `apps/ingest` (`DATABASE_URL`), `deploy/components/postgres` |
| D11 | Hosting on the organisation's OpenShift cluster and quay.io, at `dashboard.contextwindowarchitecture.io`, demo traffic only | `deploy/`; live at https://dashboard.contextwindowarchitecture.io since 2026-10-16, images `24f9dbd2beb9` (linux/amd64, private on Quay, pulled with `dashboard-pull`), Let's Encrypt through cert-manager, the demo tree published |

Two added requirements: **R-DASH-1**, item metadata is visible for every item in every redaction mode, and **R-DASH-2**, redaction is switched outside the dashboard and the dashboard names the switch. Both are tested from DP-2.

## The profile

- **Baseline**: `STYLE.md`, the CWA website's style guide at website commit `47c6ef4`, applied to this app; `AGENTS.md`.
- **Assembler**: `contextwindowarchitecture/assembler-typescript` at tag `draft-release`, commit `604b286` (`packages/assembler/pin.json`), built by `packages/assembler/scripts/build.mjs` on every install into a git-ignored `.build/` with its own lockfile and toolchain (its TypeScript is 7.0.2; ours stays 6.0.3), re-exported as `@cwa-dashboard/assembler` for the generator and the ingest service only (ADR-0003). Its tests reproduce all 65 vendored cases and reject all 25 rejections, as its published report records. Installs, CI and the ingest image build need network access to GitHub.
- **Demo traffic**: `packages/demo-traffic/fixtures/` (1.7 MB, 111 events: the 65 vendored cases and 25 rejections as `conformance-suite`, and the 21 turns of ten authored scenarios), every event `demo` and from the TypeScript assembler. `pnpm --filter demo-traffic generate` writes it; `pnpm generate --check` and the package's tests fail on a difference. Timings are measured, kept as measured, and set aside in comparisons; a regeneration that changes only them writes nothing. `--out <dir> --events N --seed S` writes a larger tree, and `--long` adds a trace of more than 400 rows and a 60-turn session (`src/long.ts`); neither is allowed for the committed tree.
- **Contract**: `packages/contract/vendor/cwa/`, 325 files of `contextwindowarchitecture/contextwindowarchitecture` at `16de4be` (clean), pinned by SHA-256 in `vendor/cwa.lock.json`. `pnpm vendor <checkout>` re-vendors; `pnpm vendor:check` fails on drift between the lock, the copy and the checkout at the locked commit. Generated types, standalone validators and the contract data as typed modules live in `packages/contract/generated/`; `pnpm generate --check` fails when they are stale.
- **Application type and primary user tasks**: a read-only observability and audit plane for CWA assemblies (plan 1).
- **Framework and routing**: Vite 8.3.3 with `@vitejs/plugin-react` 6.1.2, React 19.3.0, client-side only; React Router 8.4.0 in data mode (`createBrowserRouter`; route `handle`s name the document title and the crumb; `/` redirects to `/traces` until the overview lands). The sidebar lists only pages that exist (`src/app/navigation.ts`).
- **Runtime and package manager**: Node 24 (`engines.node >= 24`, developed on 24.20.0), pnpm 12.3.4 through `packageManager`, `saveExact` in the workspace, exact versions in every `package.json`. Packages: `@cwa-dashboard/contract`, `@cwa-dashboard/telemetry`, `@cwa-dashboard/assembler`, `@cwa-dashboard/demo-traffic`, `@cwa-dashboard/web`, `@cwa-dashboard/ingest` (the Phase 1 Node service, on Node's own `http`, with no framework) (`pnpm --filter web` matches without the scope).
- **TypeScript**: 6.0.3 in every package, strict with `noUncheckedIndexedAccess`, `erasableSyntaxOnly`, `verbatimModuleSyntax`. Not 7.0.2, although `latest` and both packages typecheck under it: typescript-eslint 8.71 accepts `typescript <6.1.0` and needs the compiler API 7 no longer exports. The maintainer chose one version everywhere over 7 beside a 6 for linting (2026-10-15); revisit when typescript-eslint supports 7.
- **shadcn**: preset `nova` on the Radix base (`style: "radix-nova"`), base colour neutral, CSS variables, Lucide; initialised with the CLI at 4.21.4, the `shadcn` dependency and later `add`s at 4.21.5. Primitives generated at DP-0: sidebar, sheet, breadcrumb, dropdown-menu, select, tooltip, button, badge, card, table, alert, input, separator, skeleton, tabs, checkbox, slider, dialog, scroll-area, with `hooks/use-mobile.ts`. Kept as generated: ESLint exempts them from `react-refresh/only-export-components` and `react-hooks/set-state-in-effect`, Prettier ignores them. Their `data-slot` restyles (STYLE.md 6) land with the first component that uses each, checked in the browser.
- **Tailwind and tokens**: Tailwind 4.3.3 through `@tailwindcss/vite`. `src/styles/globals.css` is the generated stylesheet with three changes: the two font families replace Geist, and the `dark` variant follows `data-theme`. `src/styles/tokens.css` (STYLE.md 2, 9) carries the website's block verbatim, the dashboard's size tokens and every shadcn token set from the website's in `html:root` and `html[data-theme="dark"]`; it loads after `globals.css`, and Prettier leaves it alone. shadcn's `destructive` takes `--accent`.
- **Fonts**: `@fontsource-variable/space-grotesk` 5.3.0 and `@fontsource/ibm-plex-mono` 5.3.0 (400, 500, 600), from packages because the policy serves fonts from the app's origin only (STYLE.md 2).
- **Remote data ownership and cache policy**: TanStack Query 5.104.1 over an `EventSource` (`src/data/`): an event is fresh for good; the index, sessions and the fleet report, which a store rebuilds as events arrive, refetch on focus and every 30 s while visible, and pages keep it on screen as "updating"; not-found, parse and unsupported results are never retried, network and server failures once. `/config.json` names `dataRoot` (`/data`; the plan's `eventsRoot` was renamed because the tree holds `events/`, `sessions/` and `fleet.json`) and optionally `apiBase`; dev and preview serve both from the demo tree (`dev/data-plugin.ts`, or `$VITE_DATA_DIR`).
- **Identity, tenant isolation and permissions**: none in Phase 1 (plan 11).
- **Forms and validation**: documents through the generated standalone validators (built); URL state with Zod (DP-2).
- **Tables**: the generated `Table`, restyled (STYLE.md 6). The stream sorts and filters through the URL (`features/traces/model/stream.ts`, Zod per parameter), so it needs no column state, and TanStack Table, which the plan named, is not added; it comes with an ADR-free profile line if a later table needs sorting or resizing on the client. Virtualisation (TanStack Virtual) arrives with trees above 500 rows.
- **Charts, data volume and worker thresholds**: not yet (DP-2 onward; plan 8, 9).
- **Locale, timezone and windows**: the plan's defaults (section 16): UTC with the viewer's zone on hover, the newest 24 hours by default. Not yet built.
- **Theme**: `data-theme` on `<html>`, `localStorage["cwa-theme"]` (the website's key), light by default, applied before the first paint by `public/theme.js`, a file because the policy allows no inline script; `prefers-color-scheme` is not consulted (STYLE.md 3). The masthead's toggle names the theme it would switch to and writes the key back. The sidebar's desktop state persists in the generated `sidebar_state` cookie; without one it starts collapsed at 1200px and below; it is a sheet below 768px (STYLE.md 10).
- **Supported browsers and devices**: not yet decided (DP-7). The browser tests run Chromium.
- **Content Security Policy**: defined once in `apps/web/dev/csp.ts` (`script-src 'self'`, no inline script, no eval) and sent by the dev and preview servers; the deployment's headers are held to it at DP-6.
- **Accessibility**: axe (`wcag2a`, `wcag2aa`, `wcag22aa`) in the Playwright smoke test, in both themes, and in `e2e/a11y.spec.ts` on the phone's sheet (once its slide settles) and under forced colours (without its colour-contrast rule, which there reads colours Chromium does not draw). `e2e/a11y.spec.ts` also covers the skip link, the keyboard to the stream's rows with a visible ring, focus returned by a filter's list and by the sheet, and the sidebar's collapsed state. `e2e/visual.spec.ts` loads every page type in both themes at 375, 640 (1280px at 200% zoom), 1024 and 1440px with no sideways scroll, every table and status line on the page's gutter, words whole in tables and the metric rows full. Manual checks not done: a screen reader run on the inspector; Firefox and WebKit (Playwright runs Chromium only); forced colours on a real Windows high-contrast theme (emulated here); browser zoom itself (emulated by width).
- **Performance budgets**: `apps/web/budgets.json`, gzipped: initial JS 400 kB, initial CSS 20 kB, 40 kB per lazy chunk, 120 kB per worker (plan 11). Measured at DP-7 (`899047f`): initial JS 288.0 kB (React, the router, TanStack Query and Table, the radix primitives, the contract data and the telemetry validators every data document passes), initial CSS 17.8 kB, the largest lazy chunk 34.3 kB (the contract validators the sandbox loads), no worker. Lazy: GSAP and the three choreographies, the sandbox, the reference pages and the glossary. `pnpm --filter web budgets` also fails on a library `keptOut` names in the initial JS (GSAP, by its `GreenSock` banner) and on `eval` or `new Function` in any chunk, which keeps the assembler out of every one. At DP-0 the placeholder app was 66.5 kB of initial JS and 13.4 kB of initial CSS, mostly font faces.
- **Motion**: GSAP 3.15.0 and `@gsap/react` 2.1.2, set up once in `src/lib/motion.ts` with STYLE.md 7's durations and the site's ease (through GSAP's `CustomEase`); an import test keeps GSAP inside `lib/motion` and `lib/motion` inside the three choreographies. All three are built: the inspector's stage walk (`features/traces/components/stage-walk-motion.tsx`, DP-2b), loaded when a walk starts; the played session (`features/sessions/components/session-player-motion.tsx`, DP-3), loaded when a session is first played; and the sandbox's settle (`features/sandbox/components/settle-motion.tsx`, DP-5), loaded when a replay answers. The bundler puts GSAP in one `motion` chunk they share: 29.8 kB gzipped of the 40 kB lazy-chunk budget at DP-3, when initial JS is 265.4 kB of 400 kB and initial CSS 17.3 kB of 20 kB. The illustration player: not added; the illustrations are deferred (ADR-0006), since the dotLottie player needs `'wasm-unsafe-eval'`.
- **Tests and CI**: Vitest 5.0.3 (jsdom 30.1.2, Testing Library), Playwright 1.63.0 with `@axe-core/playwright` 4.13.0. `pnpm --filter web test:perf` (`playwright.perf.config.ts`, `e2e-perf/`) generates a 50,000-event tree with `--long`, serves the production build over it with the replay service beside it, and holds the plan's budgets: a filter change on the stream's 20,000 rows under 100 ms (measured 20 ms), a 200-item replay round trip under 500 ms (213 ms), and the 432-row inspector and the 60-turn session rendering without sideways scroll at 400px. `pnpm --filter web test:e2e:api` (`playwright.api.config.ts`) runs the same smoke, accessibility and visual specs with `dataRoot` at `/api/data`, the ingest service on PGlite seeded with the demo events by a setup project, and the preview's own `/data/` empty, so every document comes from PostgreSQL (ADR-0007). CI (`.github/workflows/ci.yml`) is started by hand, like the organisation's other repositories, and runs install, the vendor check against the specification at the locked commit, `generate --check`, format, lint, typecheck, test, build, budgets, the browser tests, the browser tests over the query API and the performance tests.
- **Approved libraries and why**: React and React DOM (the app); Vite, its React plugin, Tailwind and its Vite plugin (build and styling); shadcn with `radix-ui`, `class-variance-authority`, `cn`, `lucide-react` and `tw-animate-css` (the generated primitives); the two font packages (STYLE.md 2); GSAP and `@gsap/react` (STYLE.md 7, ADR-0002); `@tanstack/react-virtual` 3.14.13 (the stream's rows above 500, DP-7; the newest release at least two weeks old); `d3-scale` 4.0.2 and its types (chart geometry in the `*-geometry.ts` modules, never the DOM, ADR-0002; first used by the turn timeline at DP-3); `d3-hierarchy` 3.1.2 and `@types/d3-hierarchy` 3.1.7 (the conflict forest's `stratify`, DP-10, ADR-0002 names it for Phase 2); Ajv and `ajv-formats` (the generated validators' runtime); `json-schema-to-typescript` (type generation); ESLint with typescript-eslint, the React hooks and refresh plugins, `eslint-config-prettier` and `globals`; Prettier; Vitest, jsdom and Testing Library; Playwright and axe; in `apps/ingest`, `pg` 8.23.1 and `@types/pg` 8.23.1 (the PostgreSQL store's client, ADR-0007) and `@electric-sql/pglite` 0.5.8 (PostgreSQL in WebAssembly, for the store's tests and a local run without a server, ADR-0007; 0.5.9 and 0.5.10 were under two weeks old).
- **Exceptions and linked decisions**: ADR-0001 to ADR-0004 (`docs/adr/`).

## Not run, by phase

- **DP-0**: CI has not run on GitHub; its steps were run locally one by one. No manual accessibility or browser-matrix checks.

- **The events worker is not built (DP-7).** The plan put the index in a worker above 5,000 rows. The index never holds more than the current window's 20,000 rows (dashboard-plan.md 3), and measured at that cap with `generate --events 50000`, the virtualised stream first renders in about 0.3 s and answers a filter change in about 20 to 50 ms on the main thread, within the 100 ms budget; before virtualisation it took 6.1 s and 1.1 s. `test:perf` holds the budget, so a regression shows; a worker comes back if it fails.
